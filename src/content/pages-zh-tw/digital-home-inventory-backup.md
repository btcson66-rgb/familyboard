# FamilyBoard 備份還原教學：先證明檔案能用，再把它當成備份

FamilyBoard 沒有帳號與家庭資料伺服器。你在 App 建立的資產、保養、保固、訂閱、任務、聯絡人與文件索引留在目前瀏覽器，因此「成功下載一個檔案」只是第一步；真正可靠的流程還要包含安全保存、只讀驗證與一次受控制的還原測試。

若只記得一件事，請記住：**瀏覽器裡的原始資料加上同一台電腦下載資料夾裡的一個檔案，不算能抵抗裝置故障的兩份備份。**

## 開始前先確認這三件事

1. 使用平常保存家庭資料的同一個瀏覽器設定檔開啟[繁中 App](/zh-tw/app/)，不要用無痕視窗。
2. 進入「設定與備份」，查看「紀錄」數量與「上次備份」時間，確認這是你要保存的家庭。
3. 檢查下載目的地有足夠空間，而且不是公開共用資料夾。若要先清除資料、匯入 CSV 或更換裝置，暫停其他修改直到備份完成。

「要求持久儲存」可以請瀏覽器降低自動回收機率，但核准與否由瀏覽器決定。它不能防止你手動清除網站資料、刪除設定檔、裝置遺失或硬碟故障，所以不能取代匯出。

## 步驟一：選一般 JSON 或加密 JSON

在「匯出備份」卡片有兩種按鈕：

| 格式 | 適合情境 | 必須知道的限制 |
|---|---|---|
| 匯出 JSON | 受你控制的加密裝置內暫存、快速測試移轉 | 檔案是明文，取得檔案的人可能直接讀取家庭紀錄 |
| 匯出加密備份 | 外接媒體、異地保存、受信任雲端或需要跨裝置保管 | 密碼至少 10 個字元；忘記密碼便無法由 FamilyBoard 復原 |

加密匯出會在目前瀏覽器內使用 PBKDF2-SHA-256、310,000 次迭代與 AES-256-GCM；密碼與家庭內容不會傳給 FamilyBoard。較長且獨特的密碼比重複使用的短密碼更可靠。密碼管理工具若適合你的家庭流程，可以用來保存密碼，但不要讓備份檔與唯一密碼只存在同一個可能同時遺失的位置。

## 步驟二：匯出並核對檔案

一般 JSON 直接按「匯出 JSON」。加密檔先在「加密密碼」輸入密碼，再按「匯出加密備份」。成功後，App 會更新上次備份時間並提示把檔案放到耐久且受保護的位置。

接著到瀏覽器下載清單確認：

- 檔名日期是今天，副檔名為 `.json`；
- 檔案大小不是 0 KB；
- 你知道檔案實際存在哪一個資料夾，而不是只看到下載通知；
- 加密檔與一般檔可以從檔名辨認，避免日後拿錯版本；
- 舊備份仍保留到新檔完成驗證，不要先覆蓋唯一可用版本。

## 步驟三：先用「只驗證備份」檢查

仍在「設定與備份」的「還原備份」卡片，若是加密檔，先輸入「加密檔案密碼」，再用「只驗證備份，不進行還原」選取剛下載的檔案。

成功訊息會顯示匯出時間、資料庫架構版本與紀錄總數，並明確寫出資料未被更動。請把總數和畫面上的紀錄規模做合理比對；驗證通過代表格式、版本與密碼可讀，不代表每一筆內容都符合你的預期。

若出現密碼錯誤、JSON 無法解析、備份格式無效或備份架構比目前 App 更新，請不要反覆嘗試真正還原。先確認檔案、密碼、FamilyBoard 網址與 App 版本；保留原始檔案，不要用文字編輯器重存加密備份。

## 步驟四：理解合併與取代再還原

「選擇要還原的備份」會立即執行你選定的模式，因此選檔前先讀完：

### 依紀錄 ID 合併

備份中相同 ID 的紀錄會更新，新的 ID 會加入；目前資料庫裡沒有出現在備份中的其他紀錄會保留。這適合把較早的資料帶入仍在使用的家庭，但合併不是智慧去重：如果同一台冰箱在兩邊是不同 ID，可能會留下兩筆，需要人工整理。

### 先建立安全快照再取代

App 會先下載一份目前資料的明文安全快照，接著清空目前 FamilyBoard 資料庫，再寫入備份內容。它適合要完整回到某個確定時間點，或在新瀏覽器中重建家庭。執行前要確認安全快照確實下載成功，因為取代後才發現拿錯檔會增加復原工作。

在完全空白、尚未建立家庭的啟動畫面，也可以用「還原既有家庭」選擇備份；此時沒有現有資料需要合併。加密檔仍必須先填入正確密碼。

## 步驟五：做一次不傷原資料的還原演練

最安全的做法是使用另一個受支援的瀏覽器設定檔或另一台你控制的裝置：開啟 FamilyBoard、從空白啟動畫面匯入剛驗證的備份，然後抽查家庭名稱、資產、保養工作、保固、訂閱與交接設定檔。

不要把「檔案能解密」當成「資料已完整」。至少抽查一筆關聯資料，例如某保養工作仍連到正確資產、某保固仍有正確到期日。測試完成後，若不需要保留該測試設定檔，再清除測試資料；不要動到唯一的正式瀏覽器設定檔。

## 家庭版 3-2-1 備份配置

數位發展部資通安全署的[基本資安防護指引](https://web.moda.gov.tw/ACS/press/news/press/19496)與國家資通安全研究院的[勒索軟體防護說明](https://www.nics.nat.gov.tw/cybersecurity_resources/promotional_resources/Protection_Guide/Ransomware_Protection/)都提出 3-2-1 概念：保留三份資料、使用兩種儲存媒體，並有一份位於不同地點；官方企業指引另建議至少一份離線。家庭可以依敏感度調整，例如：

1. 目前瀏覽器中的工作資料；
2. 拔除後妥善保存的外接媒體加密備份；
3. 另一處你信任且有適當帳號保護的加密副本。

這不是保證任何災害都能復原，而是避免瀏覽器清除、裝置失竊、硬碟故障或單一帳號問題一次帶走全部副本。官方也強調要定期演練測試與還原；對 FamilyBoard 而言，「只驗證」加上受控還原正是把這項原則落地的方法。

## CSV 為什麼不能當唯一備份？

家庭資料總表 CSV 適合用試算表批次複查與編輯，也能攜帶多種紀錄，但它不是完整災難復原格式，而且內容是明文。匯入前預覽會顯示新增、更新與錯誤列，所有錯誤修完才可執行；App 也會先下載匯入前安全快照。需要完整復原時仍以 JSON 或加密 JSON 為主。

## 常見問題

### FamilyBoard 應該選一般 JSON 還是加密備份？

兩者都是完整復原格式。一般 JSON 容易檢查與移轉，但內容可直接讀取；檔案若要放在外接硬碟、雲端或離開受信任裝置，通常應選加密備份，並把獨特密碼保存在不同且可靠的位置。

### 合併還原和取代還原有什麼差別？

合併會依穩定紀錄 ID 新增或更新備份內的紀錄，保留目前資料庫中沒有出現在備份的其他紀錄；取代會先下載目前資料的安全快照，再清空本機資料庫並寫入備份內容。無法判斷時先驗證並使用合併。

### 只驗證備份會改動目前家庭資料嗎？

不會。只驗證功能會解析檔案、檢查架構與加密密碼，顯示匯出時間、資料庫架構版本與紀錄總數，不會把任何紀錄寫入目前資料庫。

### 家庭資料總表 CSV 可以取代 JSON 備份嗎？

不可以。CSV 是供試算表複查與批次編輯的明文格式；完整災難復原仍應使用 JSON 或加密 JSON。大量匯入 CSV 前，App 也會先要求下載安全快照。

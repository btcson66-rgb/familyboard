# FamilyBoard 搬家箱件交接紀錄教學：不要把整個搬家壓成「已送達」

搬家途中有裝箱、裝載、保管、目的地點交、外觀觀察、通知與逐箱核對等不同事件。箱子到了新家，不代表每一箱都已核對，也不代表可見狀況、內容或責任已經判定。FamilyBoard 的免費[搬家箱件交接紀錄](/zh-tw/tools/moving-box-handover-log/)讓這些事件保持分層；它不修改搬家契約、不驗證業者、不計算理賠期限，也不認證箱內物品。

## 先填安全的搬家代號與情境

用 `MOVE-2026-A` 這類固定代號，不要輸入姓名、完整地址、車牌、運單、契約或帳號號碼。搬家情境可以選專業跨州、在地專業、自行租車、可移動儲存轉運，或家人朋友混合交接。情境只是在說明流程，不代表哪一套法律、保險或業者規則一定適用。

## 四個日期要留在同一條時間線

工具會要求預定或實際裝載日、可留空的目的地點交日、本次清冊檢視日與下一次箱件核對點。本次檢視不能是未來日期；裝載不能晚於檢視；目的地點交不能早於裝載，也不能晚於目前檢視；下次核對不能早於目前檢視。尚未收到搬家時，保留點交空白並使用開放中的狀態，比先填一個猜測日期更可靠。

## 每列填滿十個欄位

格式是 `ID｜箱件或品項群組｜有來源的事實｜保管人或來源角色｜事件日期｜受保護證據指標｜下一個缺口或結案理由｜負責角色｜目標或結果日期｜狀態`。每個 ID 要唯一，像 `BOX-14`，長度維持在兩到二十個英數字或連字號。事實欄描述某個來源或角色實際觀察到的內容，不要把「應該有」寫成「已經有」。照片代號或資料夾標籤可以作為指標，但不要暴露地址或內容。

## 用狀態保留事件順序

工具分開表示已裝箱、已裝載或交給保管者、已完成目的地點交、箱件未找到、可見狀況問題、通知等待回覆、已核對拆箱、遺失或損壞程序完成，以及有限存檔或外部交接。目的地總數相符，不等於每個箱號都已核對。缺件或狀況列在通知、回應或檢查尚未完成前應保持開放；只有真的有結果來源與日期，才使用完成的結果狀態。

## 正式文件和家庭索引各放一邊

來源欄可以寫估價、契約、業者清冊、保管、點交、通知與結果的安全代號。不要貼簽名、完整地址、提單號碼、私人對話、貴重物品細節或完整索賠文字。這份紀錄的價值在於指出原件並顯示缺口；把所有資料複製到共享列不但增加曝露，仍然不能證明箱內內容或責任。

## 到家後新增觀察，不要改寫過去

依控制中的清冊與簽收資料比對箱號及外觀，後來收到回覆時建立新的事件或更新目前版本，不要修改裝箱列來消除原本的不確定。若要提出通知、申訴、理賠或保險程序，回到最新契約與負責來源處理。FamilyBoard 不會代送通知、選擇估價、協商和解，也不會叫你放棄權利。

## 隱私、權限與未來商品資訊

紀錄在瀏覽器內作為家庭私有索引。原件與門禁、帳號等憑證要放在受保護系統，只分享下一個人真正需要的範圍，清除瀏覽器資料前先匯出備份。未來若出現搬家用品推薦，必須放在證據控制之外，清楚揭露聯盟關係並可跳過，不能暗示推薦搬家公司或保證理賠結果。

## 分段搬家與暫存轉運怎麼記

有些家庭不是一天完成搬遷：先把換季用品送進倉儲，再搬主要家具，最後才處理文件與易碎物。每一段都可以用新的事件 ID 和保管角色記錄，不要把三段混成一個「已送達」。如果箱件先交給朋友、再交給租車或倉儲，第二次交接要建立新的日期和來源指標；前一段的結果仍保留，接手者才知道缺口從哪個節點開始。

拍照或掃描簽收資料時，先確認影像只留下能支持當下觀察的範圍。照片不是箱內清單，也不是業者承認責任的證明；把原始檔放在受保護位置，工具列只寫安全代號與看到的事實。若目的地空間尚未整理完，記錄「暫存區已看到、箱號仍待核對」比過早標成完成更能幫助下一位家人安排時間。

## 給租屋族的交接提醒

租屋搬家常同時面對房東點交、搬家公司簽收和自己的物品核對。這三種來源的日期與責任不同，不能用一張家庭索引代替租約、點交表或正式申訴管道。把「牆面狀況」「箱件外觀」「鑰匙歸還」分成不同事件，並為每件事留下負責角色與下一步；涉及押金、損害或契約解釋時，回到當地適用的正式來源，不要讓工具的狀態文字變成法律結論。

## 關閉前自我檢查

搬家代號是否安全？裝載、點交、檢視和下次核對日期是否有順序？每列是否十欄完整且 ID 不重複？事實是否有來源角色？缺件與外觀問題是否仍可見？正式文件是否分開保存？有沒有從索引直接判定責任或期限？完整地址、憑證與貴重內容是否留在受保護位置？只要一項未完成，就先保留交接開放。

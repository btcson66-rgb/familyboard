# 漏水照片怎麼整理才有用？先安全，再建立可回查索引

漏水發生時，最容易犯的錯不是照片太少，而是為了拍得更近而走進積水、碰受潮電器，或把一張照片的推測當成原因證明。對家庭真正有用的資料，通常是「什麼時間、從哪個安全位置、看到哪個區域、原始檔放在哪裡、通知了哪個負責來源，以及之後哪一列還要複查」。

這篇針對台灣家庭搜尋「漏水照片怎麼拍、怎麼整理」的情境撰寫。它不是水電、電氣、建築、保險、租約或法律意見，也不會替你判斷照片能否證明責任。真實事件請依台電、119、供水／管理單位、租約／保單與合格專業人員的最新指示。

## 先判斷能不能拍，不要把取證放在安全前面

只要積水靠近插座、延長線、電器、電盤或其他可能帶電設備，就不要走近、碰觸或為了取景操作開關。看見天花板下垂、物件可能掉落、疑似污水、化學品、瓦斯味、火花、冒煙、受傷或無法安全離開，也應停止自行拍攝並使用所在地正式管道。遠距照片、文字觀察和「區域無法安全接近」比冒險近照更可靠。

## 用三張照片思考，而不是追求一整排照片

若站在穩定、乾燥且獲准進入的位置，可以依序思考：第一張交代區域與相對位置，第二張顯示可見水痕、滴水或積水邊界，第三張在之後相近位置記錄變化。每張照片都記日期時間和區域 ID，例如 `CEIL-1-A1`、`CEIL-1-A2`。拍不到就不要補拍想像中的角度。

照片不必包含完整門牌、帳單、信件、人臉、鄰居或門禁資訊。若管理室或廠商只需要看局部，另做裁切分享副本，並保留未編修原件。

## 原始檔、註記檔與分享副本分三層

原始檔保持不覆寫，放在家庭控制的受保護位置。FamilyBoard 的證據欄只寫安全索引，如 `LEAK-2026-01-A1`，不要把整張照片或私人訊息貼進公開交接。若需要在副本上加箭頭、裁切或馬賽克，檔名標明 `share-copy` 或「分享副本」，讓收件人知道它不是原始檔。

這三層的目的不是證明一定會獲得理賠或對方一定有責任，而是讓家庭之後能回答：哪一張是最早的原件？哪一張只供分享？哪個觀察連到哪個區域？

## 區域 ID 讓不同日期不會混在一起

為每個受影響的小區域建立 ID，例如天花板 `CEIL-1`、櫃體 `CABINET-1`、地板 `FLOOR-1`。同一個 ID 可以連回第一次觀察、後續照片、管理回覆、授權工作單和乾燥複查。若幾週後另一處再次出水，建立新 ID 或新事件，不要只把最新照片塞進舊資料夾。

區域 ID 只是一個家庭索引，不是建築診斷。不要因為水痕位在某房間，就在檔名寫「樓上管線破裂」；把這類說法留給正式來源或合格查核。

## 把照片時間和「第一次看到」分開

照片建立時間、手機同步時間、家人第一次看到時間和管理通知時間可能不同。紀錄時分別標示來源：例如「家人 09:30 第一次看到」與「手機原始檔顯示 09:42」。不要把檔案時間自動當成漏水開始時間，也不要因後來找到更早照片就覆寫原始觀察。

## 通知與修繕證據不要藏在照片裡

照片只回答外觀，通知紀錄要另外保存：負責角色或單位、查核過的管道、日期、回覆索引與下一個行動。修繕也要分開記授權來源、到場日期、工作內容索引和之後的複查。水停止、表面變乾與修繕完成不是同一件事。

用[家庭漏水事件紀錄表](/zh-tw/tools/household-water-leak-event-log/)把照片索引接到同一事件，再看[FamilyBoard 漏水紀錄 App 教學](/zh-tw/guides/familyboard-water-leak-event-log-tutorial/)了解如何指定每個開放區域的負責角色。這兩頁是紀錄工作流程，不會替你判斷來源或安全。

## 分享前做一次個資與範圍檢查

逐張檢查照片邊角是否出現住址、信件、帳戶、電話、門禁、孩子、鄰居或私人訊息；再確認收件人真的需要整個事件，還是只需一個區域與日期。把不必要的內容留在受保護原件，不要因「證據越多越好」而擴大個資副本。

## 聯盟行銷界線

未來若出現標籤、收納或備份用品推薦，只能放在教學內容之後、清楚揭露且可略過。商品不能改善漏水、保證理賠、選擇修繕廠商或改變 FamilyBoard 的紀錄狀態；不買任何商品也能完成索引。

# FamilyBoard 加密備份密碼教學：保護 JSON 匯出檔並保留復原能力

加密匯出是為了降低 JSON 復原檔在瀏覽器外保存或搬移時被直接讀取的風險。FamilyBoard 在瀏覽器內使用 PBKDF2-SHA-256 與 AES-256-GCM 處理加密，密碼就是解密所需的復原金鑰。App 不會上傳、保存或替你重設密碼，因此密碼選擇、檔案保存和實際測試必須分開安排。加密可以保護檔案內容，卻不會自動建立雲端同步，也不能保證原本的瀏覽器永遠存在。

## 匯出前先決定密碼流程

使用長而獨特的密語，並透過密碼管理器或其他受控方式讓獲授權的家庭復原角色找得到。不要重用供應商帳密，不要把卡號放進密語，也不要把密碼寫入 FamilyBoard 備註。App 會拒絕短於十個字元的密碼，但通過最低長度不代表安全。按下「加密匯出」以前，先確認誰可以取用、角色更換時怎麼交接，以及緊急說明放在哪裡。

## 將檔案與密碼分開保存

在「匯出備份」輸入密碼後選擇加密匯出。App 會下載帶有 encrypted 標示的 JSON 檔，並記錄成功匯出時間。把檔案移到瀏覽器之外、權限受控且可以長期保存的位置；密碼則放在另一個受控系統。檔名不應透露住址、敏感資料類別或密碼。如果下載中斷，重新匯出並確認最新完整檔案，不要把半份下載當成可復原副本。

## 先做解密驗證，再考慮還原

開啟「還原備份」，輸入相同密碼後使用「不還原只驗證」。成功時會顯示匯出時間、架構版本和紀錄總數，不會清除或更新任何本機資料表。密碼錯誤時不要在共用螢幕上反覆猜測；回到約定的受控來源確認密碼、檔案和裝置。不要用文字編輯器改加密位元組，也不要只改檔名就宣稱已測試。

## 角色變動時要輪替

家庭復原角色更換時，建立新的加密檔與新的密碼，並依家庭留存決策處理舊檔。若舊檔仍保留，要寫清楚範圍和誰有權限。密碼遺失時，FamilyBoard 無法破解；實際做法是尋找另一份有效匯出或明文備份，而不是削弱加密。明文 JSON 只有在內容可接受、保存位置受控時才使用。

## 加密不會保護所有東西

瀏覽器裡的即時家庭資料仍可能被能開啟 App 的人讀取；截圖、複製到筆記的內容、位置參照和原始附件也不會因 JSON 加密而自動受保護。分享前要檢查名稱和指標。日後若旁邊出現密碼管理器或儲存媒體的聯盟商品，會揭露並可跳過；商品不能找回遺失密碼，也不能代替免費的驗證流程。

家庭可以把「誰保存密碼、檔案放哪裡、多久驗證一次」寫成簡短交接事項。每次更新重要紀錄後重新匯出，並在不影響正式資料的前提下做唯讀驗證；這比只看檔案名稱或下載日期更能確認復原路徑仍可用。若裝置即將轉手，先建立新的副本和角色交接，再撤回舊位置權限。

驗證時也要看紀錄總數是否符合預期，並抽查文件與附件的安全參照。數量正確不等於內容最新，解密成功也不代表保存裝置沒有故障；兩者都要由家庭角色觀察並寫下日期。若同一份檔案需要交給不同角色，使用最小必要範圍，不要讓整個密碼管理庫或整個家庭設定檔都暴露。當密碼保存方式變更，重新做一次小型復原演練，確認新角色知道從哪裡取得密碼、檔案和操作說明。

不要把加密檔放在 FamilyBoard 自己的附件位置再宣稱已完成異地保護，因為附件中繼資料只是索引。檔案所在位置、密碼所在位置和瀏覽器目前資料是三個不同的風險面；分開管理並留下可追溯的交接觀察，才能在換機或角色變動時快速判斷缺少哪一環。

若只是要傳給授權者做一次驗證，可以先確認檔案收件位置，再於驗證後撤回分享權限。不要因為加密就忽略檔名、下載資料夾或螢幕旁的紙本密碼。

**情境 CTA：** 決定受控的密碼流程，匯出一份加密檔，並完成一次不還原的驗證。

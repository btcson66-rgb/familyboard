# FamilyBoard 家庭總表 CSV 編輯匯入教學：先預覽，再更新資料

FamilyBoard 的家庭總表是一份 UTF-8 CSV，適合用試算表複查和受控的大量編輯，但不能取代完整 JSON 備份。安全做法是先匯出、只編輯工作副本、載回預覽、修正全部錯誤，確認後再下載匯入前安全快照並套用。這樣可以利用試算表整理多筆資料，又不把它誤當成直接操作資料庫的工具。

## 先匯出兩種不同用途的檔案

在家庭總表卡片選擇匯出 CSV，保留原始檔不修改，再複製一份到試算表工作。空白模板只適合規劃新列，不含目前家庭，不能當備份。若要進行大量變更，先另行匯出 JSON，讓復原起點和 CSV 編輯範圍清楚分開。

## 保留 ID 和欄位結構

每一列都有紀錄類型、穩定 ID，以及該資料表需要的欄位。合併會用穩定 ID 找回原列，所以不要排序到 ID 欄、改欄名、刪必填欄位，或貼入匯出後變成意外文字的公式。附件列只有名稱、MIME 類型、大小和位置參照，沒有實際檔案。密碼、簽名網址和完整私人文件不要放進 CSV。預覽出現略過家庭描述或來源待核對的警告時，要逐項判斷，不要只看新增筆數。

## 合併和追加要分清楚

合併會更新相同 ID 並加入有效新列，適合把一份已知匯出檔的修訂套回同一個家庭。追加會建立新的 ID 副本，只有在你真的要匯入另一組獨立資料時才使用，否則容易產生重複。兩種模式都不會替你判斷哪個值比較新；如果兩個人各自修改了不同匯出檔，先保留兩份原檔並人工解決衝突。

## 先看預覽再按套用

選擇「匯入家庭總表 CSV 供預覽」。App 會限制檔案不超過五 MB、解析 UTF-8 列，並顯示新增、更新和略過的數量。任何驗證錯誤都必須先修正；檢查日期、相關資產 ID、紀錄類型、空白名稱和意外的私人文字。成功匯入前會下載目前家庭的 JSON 安全快照，請在瀏覽器外確認它已保存。

## 匯入後重新確認

看到成功訊息後，到相關畫面抽查幾筆更新列，重要修改再匯出一次 JSON。記下使用哪一版 CSV、誰看過預覽、選了合併還是追加。如果結果不對，立即停止後續編輯，保留安全快照和原始 CSV，再有意識地決定是否復原。試算表軟體或資料夾的聯盟商品若日後出現，會有揭露且可跳過；它們不能判斷家庭語意，也不能取代 JSON 復原檔。

可以把每次匯入視為一次小型變更審查：檔案來源、修改目的、影響列數、快照位置和驗證人都留下來。若只是要調整一個名稱，不必為了方便而把整張表交給不熟悉家庭資料的人。縮小編輯範圍，反而能降低錯誤、重複與隱私外洩的機會。

若需要多人協作，指定一份「目前可編輯」的工作副本，並在檔名或交接紀錄標示匯出日期。不要讓兩個人同時從舊 CSV 建立追加副本，否則穩定 ID 和實際家庭狀態很快會分岔。匯入後把預覽數字、成功訊息和抽查結果放在同一筆變更記錄，下一個人才能知道哪些列已套用、哪些警告仍待處理。若資料來源本身有錯，回到來源修正後再匯出，不要在表格裡猜測正式值。

CSV 也可能包含位置參照、供應商名稱或家庭角色線索。把工作檔放在受控資料夾，完成後刪除不再需要的副本並依家庭留存規則處理；這是資料治理決策，不是 App 自動替你完成的安全保證。重要結果仍應以 JSON 備份和原始來源為準。

套用前最後再檢查一次家庭名稱與列數；若預覽顯示的規模和預期差太多，先取消並找出原因。小心的停下來，本身就是 CSV 工作流程的一部分。

多人一起編輯時，先在交接處標明「目前可編輯」的唯一工作副本與匯出日期，不要讓不同人從舊檔各自追加。完成後清除不需要的副本，並保留來源與快照的查核紀錄。

**情境 CTA：** 匯出家庭總表與 JSON，僅修改工作副本，完成預覽後寫下匯入模式再套用。

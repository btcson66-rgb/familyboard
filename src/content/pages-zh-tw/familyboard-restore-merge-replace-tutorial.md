# FamilyBoard 備份還原合併與取代教學：選擇安全復原路徑

選擇還原模式前，先問自己：「這份檔案是要補進目前家庭，還是要成為這個瀏覽器的完整新狀態？」FamilyBoard 會在寫入前驗證 JSON 備份。**合併**會依穩定紀錄 ID 更新檔案中相同的資料、加入檔案中的新資料，並保留只存在目前瀏覽器的紀錄。**取代**則會先下載安全快照，再清空本機資料表並寫入已驗證的備份。工具不會替家庭判斷哪一份比較新，所以日期、範圍和復原原因都要由使用者確認。

## 先驗證，不要直接選還原

在「還原備份」卡片先使用「不還原只驗證」的檔案選擇器。明文 JSON 會顯示匯出時間、資料架構版本和紀錄總數，但不會更動瀏覽器資料庫。加密檔案則需要建立時使用的密碼；忘記密碼時，FamilyBoard 無法替你找回。驗證失敗時，保留目前資料，回到受控的備份位置取得另一份檔案。不要用文字編輯器硬改 JSON，因為加密驗證或欄位結構可能因此失效。

## 目前資料可能較新時使用合併

合併是比較保守的選擇。備份裡有相同穩定 ID 的列會被更新，新的列會加入，而只在目前瀏覽器出現的列不會被刪掉。這適合從另一台裝置帶回一批已知資料，或手上的檔案只包含匯出當時可取得的部分資料表。不過，合併不是自動比對每個欄位的「最新版本」：如果舊備份和現在都有同一個 ID，舊內容仍可能覆蓋較新的文字。因此要先比較檔案匯出日期、目前上次備份日期與家庭成員記得的最近修改。

## 完整重建時才使用取代

取代適用於清楚的復原邊界，例如新的瀏覽器設定檔、受控的裝置搬遷，或確認現有本機資料已損壞而備份代表完整狀態。執行前核對檔名、匯出日期、家庭名稱和預期紀錄數。FamilyBoard 會在清除前下載 `familyboard-safety-snapshot-時間.json`。下載提示出現不等於檔案已妥善保存，請到平常使用的備份位置確認檔案真的存在，再繼續處理。若目前資料有尚未匯出的新工作，取代會讓它消失，所以不應只為了畫面整齊而選取代。

## 兩種模式怎麼比較

| 判斷問題 | 合併 | 取代 |
| --- | --- | --- |
| 備份沒有的目前紀錄 | 留在瀏覽器 | 取代前快照後會被清除 |
| 相同穩定 ID | 由備份更新 | 由備份重新建立 |
| 適合情境 | 補資料、整合一份已知副本 | 用完整可信副本重建 |
| 主要風險 | 舊列覆蓋相同 ID 的新內容 | 未匯出的目前紀錄被清除 |

## 還原後要逐項檢查

把選擇理由、信任的匯出日期和執行者寫在家庭交接紀錄。還原後抽查家庭名稱、成員、近期任務、文件指標與附件中繼資料。App 顯示的「上次還原」時間只能證明動作發生，不能證明每一列都正確。如果發現遺漏，先停止編輯，保留來源備份與安全快照，再決定下一步。調查期間不要刪掉唯一副本。

FamilyBoard 的免費功能不需要帳號或付費方案就能驗證、合併和取代。未來若在文章旁放置儲存媒體或資料夾等聯盟商品，會標示揭露並保持可跳過；商品不能保證復原，也不能取代自己的備份流程。

如果家庭共用同一台裝置，還要把模式選擇告知其他使用者。合併後留下的紀錄不一定來自同一個匯出時間，取代後的安全快照也不會自動上傳或永久保留。建議在交接筆記寫出「檔案來源、匯出日期、選擇模式、檢查項目和仍待確認的問題」，讓下一個人能重播判斷。當不同備份各自有重要修改時，先保存兩份原檔，再以人工比較和明確決策處理，不要反覆按取代期待 App 猜出正確答案。

復原完成後若要繼續編輯，先再匯出一次目前狀態，讓新一輪歷史有清楚起點。任何「看起來不對」都應記成待查問題，而不是立刻刪除另一份備份。

**情境 CTA：** 先驗證一份備份，將匯出日期與目前家庭狀態比較，再寫下一句選擇合併或取代的理由。

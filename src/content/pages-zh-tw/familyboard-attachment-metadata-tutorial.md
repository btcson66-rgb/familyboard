# FamilyBoard 附件中繼資料教學：只記索引，不上傳檔案

附件中繼資料回答的是「授權的家庭角色應該找哪一個檔案、到哪裡找」，不是「FamilyBoard 能不能下載或還原這個檔案」。FamilyBoard 會在瀏覽器本機保存名稱、MIME 類型、位元組大小和位置參照，並加上一般紀錄的 ID 與時間。PDF、照片、掃描檔或試算表仍留在家庭控制的資料夾或服務中。這條界線讓免費 local-first App 能夠建立清楚索引，又不假裝自己是雲端硬碟。

## 先建立安全的位置參照

名稱要能辨識檔案，但不必公開多餘個資，例如「熱水器保固 2026」或「租屋檢查照片」。MIME 類型是格式標籤，例如 `application/pdf` 或 `image/jpeg`，不是安全性保證。大小是建立紀錄當下觀察到的位元組數，原始檔案編輯後可能變得過時。位置參照應指向授權資料夾、文件索引或受保護來源，建議使用安全代碼。不要把密碼、私鑰、短期簽名網址、完整病歷敘述或信用卡資料貼進欄位。

## 連到正確的家庭紀錄

如果檔案支援某個物品或事件，就使用文件或資產索引建立關聯。家電保固掃描檔可以指向對應資產，檢查照片可以指向文件或維護事件。不要只靠相似檔名猜測關係；在備註或相關紀錄留下清楚的參照。檔案搬家時，更新位置並記下變更日期。供應商替換文件時，先保留舊觀察再新增新中繼資料，日後才分得出來是哪一個版本曾被查核。

## 分享或匯出前要做隱私複查

檔名本身就可能揭露租屋地址、孩子學校、醫療類別或私人供應商。分享家庭總表 CSV 或 JSON 備份前，逐項檢查名稱、位置參照和備註。總表的 `attachment` 紀錄類型包含名稱、MIME 類型、大小和位置參照，用途是複查與受控大量編輯，不是上傳檔案內容。JSON 備份會把附件中繼資料包含在完整本機復原包裡；若儲存位置不是本來就受保護，應使用加密匯出，並把密碼放在另一個安全位置。

## 一次實用的附件檢查

1. 先在受控來源確認原始檔案可以開啟。
2. 將目前檔名、格式和位元組大小與中繼資料列比較。
3. 位置改變時只更新安全參照，不要把檔案複製進 FamilyBoard。
4. 確認關聯的資產、文件或維護事件沒有接錯。
5. 重要修改完成後匯出 JSON，並用唯讀驗證檢查副本。
6. 找不到原始檔案時標成「待處理」，再由授權來源尋找復原方式。

## App 不會替你保證什麼

FamilyBoard 不會掃描你的資料夾、不會跨裝置同步附件、不會驗證檔案完整性、不會代替來源系統管理權限，也不能找回已刪除的原始檔案。位置參照更不代表每個人都有權限開啟來源。請使用資料夾或服務本身的分享控制；家庭角色改變時，更新安全參照與交接說明，不要散播秘密連結。

如果檔案名稱包含住址或身分資訊，可以在 FamilyBoard 使用較中性的索引名稱，再把詳細名稱留在受控來源。當多人輪流維護時，指定一個人定期比對大小和格式，另一個人確認權限仍符合家庭角色；這是人工複查，不是 App 的自動保證。附件已被替換、搬移或撤銷時，保留舊列的查核日期與原因，再新增新的指標，避免歷史突然消失。這樣即使只有中繼資料，日後也能知道哪個檔案曾經支援哪項家庭決策。

複查時可以把「原始檔案已確認」「位置待更新」「權限待確認」分開記錄，避免用一個模糊的完成標籤掩蓋問題。若要交給新家庭角色，交接安全代碼和查核日期即可，絕對不要把登入資訊一起放進索引。

未來若在本教學附近放置資料夾、標籤或掃描配件的聯盟商品，會清楚標示揭露並保持可跳過。商品不能替你加密、上傳或還原檔案。可靠的免費流程很簡單：名稱清楚、格式與大小盡量準確、位置參照安全，並另外保存原始來源的耐久備份。

**情境 CTA：** 複查三筆附件中繼資料，移除所有秘密權杖，再逐一對照受控來源的原始檔案。

# FamilyBoard Offline Backup and Restore Guide

FamilyBoard is a local-first household workspace: it helps a family keep tasks, records and handoff notes available without turning the public website into a data account. The useful habit is not merely entering information. It is setting up a private space, deciding what belongs there, exporting a backup, and periodically testing that the backup can be restored.

## Start with a small private household space

Create only the categories your household can maintain: recurring tasks, home records, contacts, maintenance notes and a handoff area. Use household labels rather than unnecessary identifiers. Do not put passwords, payment credentials, medical details or access codes into general notes. The public pages explain the product; the app is where private household data belongs.

Before adding a large inventory, open the app once while connected, create one harmless sample item and close it. Reopen it to confirm the local workflow. This small test shows which browser profile and device contain the data and prevents a family from assuming that two devices are automatically synchronized.

## Understand offline use

The app shell and local data must be available on the device before an offline visit can work. Connect first, open the app, and wait for the normal interface to finish loading. Then test with the device’s offline mode or a temporary network disconnect. A successful offline open means the app can load locally; it does not mean a backup exists or that another device has the same data.

If offline opening fails, reconnect and use the current browser storage and service-worker controls. Do not clear site data while troubleshooting unless you have a verified export. Clearing storage can remove the only local copy.

## Export a backup with a custody label

Export from the app’s backup control and save the file in a private location with a non-sensitive label such as `HOUSEHOLD-BACKUP-2026-08`. The filename should not contain names, addresses or account details. Treat the file like a household document: limit access, keep a second location when appropriate, and record when it was created.

An export is a snapshot, not a live sync. A newer change is not in an older file unless you export again. Keep a short note of the app version and the categories included, but do not paste the backup contents into a shared chat or public tool.

## Test restore instead of trusting the filename

Use the app’s restore flow in a controlled profile or test device. Confirm that the backup opens, the expected sample records appear, and private fields are still treated as private. A successful restore test is evidence that this file can be read; it is not proof that every historical change or every device is covered.

If a restore reports an error, keep the original backup unchanged, record the error code safely and use the current product instructions. Do not repeatedly overwrite the only copy while experimenting.

## Share a handoff without sharing the database

When another household member takes over, share the categories and responsibilities they need, not the complete backup. A handoff can state “maintenance list reviewed; emergency contacts location confirmed; next export due” while leaving the underlying records in the protected app. This is safer than emailing a full export.

## What FamilyBoard does not promise

The app does not replace a professional backup service, a legal record system, a medical record, a bank, a password manager or an emergency dispatch channel. It does not guarantee recovery from every device failure. Review the current privacy, security and product pages before deciding what information belongs in the app.

## Future products and unobtrusive affiliate space

General storage products, folders or backup drives may be useful around this guide in the future, but they must not interrupt the backup or restore controls. A product cannot guarantee recovery, security or synchronization and cannot replace a verified restore test.

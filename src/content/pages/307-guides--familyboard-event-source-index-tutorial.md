# How to Use FamilyBoard for a Household Event Source Index

Family records often fail at the handoff point. One person remembers seeing a notice, another has a photograph, and a third knows that a provider replied—but nobody can tell which version was checked or where the original is protected. The FamilyBoard source-index workflow gives that narrow problem a repeatable home. It records a safe event code, a real check date, the responsible source's role, a minimal observation pointer and one next owner.

This is not a document vault or a source-authentication service. It is a map for authorized household members. The original notice, photograph, contract, manual, message or claim file remains in the protected location controlled by the household or responsible issuer.

## Step 1: Name the event without exposing the household

Start with a neutral code such as `OUTAGE-A`, `LEAK-2` or `SERVICE-APRIL`. The code should help the household connect related rows without revealing an address, phone number, account, case number, password or person's name. If an event changes scope, create a new code or version instead of quietly rewriting the old one.

## Step 2: Record the date you actually checked

The check date answers “when did someone open or verify this source?” It is not automatically the source's publication date, the date an event began or a deadline. If the source exposes a version, issue or notice date, keep that as a separate observation in protected notes. If no version is shown, write `version not stated; checked YYYY-MM-DD` rather than inventing one.

## Step 3: Describe the source's role

Use a role that a later reader can test: `building notice / access update`, `manufacturer manual / cleaning section`, `utility statement / service status` or `provider reply / appointment record`. Avoid conclusions such as “building caused the leak” or “equipment is safe.” The source role says what the document or organization is responsible for; it does not transfer that responsibility to FamilyBoard.

## Step 4: Link a protected pointer to a minimal observation

Write a pointer such as `NOTICE-2`, `PHOTO-LEAK-A3` or `MANUAL-4` and a short fact: `hallway observer saw ceiling stain`, `current support page opened`, or `reply received; appointment detail remains in protected message`. Do not paste full notices, photographs, addresses, signatures, medical details, credentials or private conversations into the shared row. A pointer is useful only if an authorized person can locate the protected original and knows when it was checked.

## Step 5: Give the next person one observable action

“Recheck current notice version | household administrator” is a testable next step. “Handle later” is not. If the source conflicts with another source, leave the row open, record both safe pointers and route the question to the responsible issuer, building role, provider, insurer or qualified professional. The workflow does not choose the version that sounds most reassuring.

## Use the right FamilyBoard tool

The [Household Event Source Index Log](/tools/household-event-source-index-log/) creates the minimum row described here. When two observed timestamps need arithmetic, use the [Household Event Duration Calculator](/tools/household-event-duration-calculator/) and return the result with both observations intact. A long repair sequence belongs in the repair evidence timeline; a digital binder can hold pointers across many record classes. Tools complement one another, but none replaces the controlling source.

## Version changes are evidence, not clutter

Create a new row or version when a notice is replaced, a support page moves, a file is relocated, the event scope changes, a new person takes ownership or a provider gives a different response. Keep the earlier date because it shows what the household knew at that time. A downloaded PDF called `latest` is not permanently current, and a copied screenshot does not prove authenticity by itself.

## Privacy, sharing and affiliate boundaries

Before sharing an index, remove anything that identifies an unintended person, address, account, case or exact protected location. FamilyBoard's browser tools do not transmit these fields to a server, but a downloaded or printed result becomes a new copy that needs its own review. Future recommendations for label makers, scanners or document storage may appear after the educational answer with a clear disclosure and an easy skip. A commission cannot authenticate a source, select a provider, decide a claim or close an unresolved event.

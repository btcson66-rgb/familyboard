# A household handoff is the operational version of “here is what you need to know”

If one person normally manages the home, a temporary absence can reveal how many responsibilities were invisible: bill reviews, repair follow-ups, pet routines, contractor visits, renewals and maintenance. A household handoff turns that invisible knowledge into a dated, purpose-built route through the records. It is not a data dump and it is not the same thing as merely naming a backup person.

The useful question is: “What does this recipient need to do next, what source controls the answer, and what must remain private?” Start with those three boundaries before choosing a format. A printed sheet may be right for a house sitter; a local App view may be better for a partner who needs to update tasks; a contractor may need only an asset code and a protected service report pointer.

## Build the handoff from current obligations

Start with the next 30 days: tasks, appointments, maintenance, renewals and expected household issues. Then add essential contacts and ongoing responsibilities. Put the date the handoff was prepared at the top, name the intended audience and state when it expires. A trip handoff prepared in August should not silently become the source for a December move.

For each item, include an owner or escalation role, a due or appointment date, a safe source pointer, the next observable action and the condition that closes it. “Call plumber” is an action; “appointment confirmed” is an observed external result; “repair completed” needs the provider report or household recheck. Keeping these states separate stops a prepared instruction from being mistaken for a completed outcome.

## Include why, not only what

“Call plumber” is less useful than “upstairs sink had a recurring leak; prior service report is `REPAIR-A7`; check the current provider pointer before booking; next review 2026-09-03.” The second version gives context without copying a phone number, address or private conversation into a shareable document. Use stable neutral IDs that let the recipient find the protected source through the agreed route.

Explain vocabulary that only the primary manager knows. If “green folder” means the cloud portal copy and “blue folder” means the fireproof-box original, write that mapping. If an account change requires a provider's authorised transfer process, say so instead of storing a password. A handoff should reduce guesswork, not create a new secret notebook.

## Protect private information

A handoff summary should be generated from selected data, not grant blanket access by default. Exclude credentials, payment details, full identity numbers, medical notes, private messages and document contents unless a protected workflow specifically authorises them. FamilyBoard's handoff view filters sensitive contacts and high-detail fields, but even a non-sensitive task title can reveal more than intended; review the wording before printing or placing it on a shared screen.

Keep a private record of who received the handoff, which version and how it will be returned or destroyed. If a recipient needs a document, share the controlled source rather than creating a second uncontrolled copy. When a fact changes, invalidate old printed sheets and update the current record before generating another version.

## Make it reusable

After the absence, ask the substitute manager what they had to ask, which pointer was stale and which responsibility had no clear owner. Update the underlying household record and the reusable structure, but do not overwrite the dated handoff that proves what was actually shared. The system becomes stronger each time because it learns from a real transfer rather than an imagined checklist.

Test before the high-pressure moment. Give the intended recipient one task and five minutes to locate the source, identify the responsible role and state the next checkpoint. If they cannot, shorten the handoff, improve names or repair the source map. More pages and more fields do not compensate for a route nobody can follow.

The App remains local-first: records are stored in the current browser and are not synchronised to a FamilyBoard account. Export a backup before clearing browser data, and keep the handoff itself within the privacy boundary chosen for its audience. Future affiliate recommendations for folders, labels or travel organisers must remain outside the operational instructions, clearly disclosed and optional.

# Household Backup Recovery Checker

A FamilyBoard household can look healthy in the browser while its only backup is an unlabeled download nobody has opened. This free local tool creates a small readiness index: the most recent export date, the last retrieval test, the scope that was actually observed and the next date a household role will test again. It never reads your files or sends data anywhere.

## What the checker validates

The form requires a neutral review code, four ordered dates, a protected storage pointer, a current status and at least one scope line. It catches future review dates, a recovery test dated before the export, missing scope columns and common credentials or identifier patterns. The result then lists each scope's observed retrieval and next action so another permitted role can understand what remains open.

Use a code such as `BACKUP-REVIEW-2026-A`, not a person’s name or a filename containing an account number. A scope line can say `assets and maintenance | BACKUP-2026-A | test copy opened and version identified | compare the latest maintenance change`. Keep the full path, encryption password and original file in the protected storage system.

## What it cannot prove

The checker does not inspect IndexedDB, open a download, decrypt JSON, compare every record, upload a copy or test another device. A green-looking summary is not proof that a backup is complete, current, readable by every role or suitable for a legal, financial, medical or emergency decision. Perform the real retrieval with the authorised role and record only the observed result and a safe source pointer.

## A practical five-minute drill

First export a JSON snapshot from FamilyBoard without editing it. Confirm the file exists in the protected location and that the date and version are identifiable. Next use the appropriate restore or test environment to open a copy, check one asset, one task, one document pointer and one contact boundary, then close without overwriting the working copy. Finally return to the checker and record what was actually seen, what was not checked and who owns the next drill.

If a household uses more than one device, name the current source-of-truth version in its protected procedure. Do not merge two untested exports simply because their filenames look similar. Keep the untouched original until the new copy has passed the household's retrieval test.

## Protect exports and plan the next test

JSON backups contain the complete local database, including private notes and contacts. Store them separately from the browser profile with access appropriate to the household. The checker itself is a planning note, not an access-control system. A future affiliate placement for storage media or backup software must be outside the form, clearly disclosed and optional; a product cannot make a recovery file complete or safe.

**Next step:** run the real retrieval drill in the protected system, update the observed scope in this checker and leave the next test date assigned to a role that can actually perform it.

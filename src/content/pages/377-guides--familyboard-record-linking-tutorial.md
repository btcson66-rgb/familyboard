# Link the story of one household asset before you need to make a decision

A washing machine, water heater or laptop rarely has only one useful fact. Its purchase record, model label, warranty, manual, service visit and next maintenance task answer different questions, but they all describe the same physical item. FamilyBoard's links let you find that context without pasting every file or credential into one crowded note.

## Start with one stable asset

Open the Assets tab and create one record for the physical unit. Use a neutral name that another household member can recognize, such as `Kitchen washer` or `Study laptop`; add the model and serial number only when the household has a safe reason and a protected storage plan. If a label is hard or unsafe to reach, leave it unknown and point to the next service visit rather than making a risky climb.

Do not create a second asset because a warranty email, repair invoice or replacement filter appears. The asset is the stable thread. A new record is appropriate when the physical unit is replaced, sold, donated or separated into a genuinely different item.

## Add the records that answer different questions

Attach a maintenance task for what needs to happen next, a warranty for the written coverage window, and a document reference for the manual or receipt location. Each remains its own record because its source, date and status mean something different. A completed filter change is not the same fact as a warranty end date, and a receipt location is not proof that a repair was successful.

Use the same asset label or relationship field each time. In notes, prefer a safe pointer such as `MANUAL-WASHER-02` or `RECEIPT-FOLDER-A` to a public URL, full address, account number or password. The goal is a reliable path back to the controlling source, not a duplicate document repository.

## Record events without overwriting history

When a technician visits, add a dated maintenance or service event describing what the household requested, what the provider reported, what was authorized and what the household observed afterwards. Keep “repair requested,” “provider says complete” and “works after recheck” as separate states. If a recurring symptom returns, add another event linked to the same asset instead of editing the old event until it looks resolved.

The relationship makes the timeline useful during a handoff. A substitute household manager can open the asset, see the next due task, find the safe source pointer and understand which result still needs confirmation. Sensitive contacts, payment details and full files stay in their appropriate protected systems.

## Use a small review exercise

Pick one asset with a real upcoming decision. Check that its name is stable, its next task has an owner and date, its warranty uses the written term, and its document pointer still leads an authorised person to the current source. Then ask a second household member to find the next action without an explanation from you. If they cannot, improve the label or relationship before adding more fields.

FamilyBoard is local-first: the linked records remain in the current browser and are not uploaded to a FamilyBoard server. Export a protected backup before clearing site data or moving to another device, and test the backup on a controlled copy. A future affiliate block for labels, folders or storage media must sit outside the workflow, be clearly disclosed and remain optional; no product is required to create or link a free record.
